DevAuthKit Complete Documentation

DevAuthKit is a zero-config, plug-and-play self-hosted authentication toolkit for Node.js, Express, and Cloudflare Workers (Hono). It provides hardware-bound RFC 9449 DPoP token defense, WebAuthn passkeys, passwordless email OTP, rotating refresh tokens, and database adapters for Prisma, Drizzle, and Mongoose with zero monthly active user (MAU) billing limits.

npm install devauthkit

Quickstart Guide

Mount a production-ready authentication engine in less than 3 minutes.

const express = require("express");
const devAuthKit = require("devauthkit");

const app = express();

// Initialize DevAuthKit (Zero-config dev mode prints OTP to console)
devAuthKit(app, {
  jwtSecret: process.env.JWT_SECRET || "your-secret-key",
  sessionSecret: process.env.SESSION_SECRET || "your-session-key",
  corsOrigin: ["http://localhost:3000", "http://localhost:5173"],
  devMode: true
});

// Protect routes with triple-strategy requireAuth middleware
app.get("/api/dashboard", devAuthKit.requireAuth, (req, res) => {
  res.json({ message: "Authenticated", user: req.user });
});

app.listen(3000, () => console.log("DevAuthKit server ready on http://localhost:3000"));
import { Hono } from "hono";
import { createHonoAuth, CloudflareD1RefreshTokenStore } from "devauthkit/hono";

const app = new Hono();

export default {
  async fetch(request, env, ctx) {
    const auth = createHonoAuth({
      jwtSecret: env.JWT_SECRET,
      d1: env.DB,
      refreshTokenStore: new CloudflareD1RefreshTokenStore(env.DB)
    });

    app.route("/auth", auth.routes);

    app.get("/api/user", auth.requireAuth, (c) => {
      return c.json({ user: c.get("user") });
    });

    return app.fetch(request, env, ctx);
  }
};
import React from "react";
import { AuthProvider, useAuth } from "devauthkit/react";

function UserProfile() {
  const { user, isAuthenticated, sendOTP, verifyOTP, logout } = useAuth();

  if (!isAuthenticated) {
    return <button onClick={() => sendOTP("user@dev.io")}>Login with OTP</button>;
  }

  return (
    <div>
      <h2>Account: {user.email}</h2>
      <button onClick={logout}>Sign Out</button>
    </div>
  );
}

export default function App() {
  return (
    <AuthProvider>
      <UserProfile />
    </AuthProvider>
  );
}

Enterprise SSO (SAML 2.0 & Enterprise OIDC)

Zero-fee, self-hosted enterprise Single Sign-On engine for Okta, Microsoft Entra ID (Azure AD), Google Workspace, OneLogin, and PingFederate. Features pure-JS XML Exclusive Canonicalization (C14N), RSA-SHA256 signature verification, dual rolling X.509 certificate rollover, and strict defenses against XXE, XML Signature Wrapping (XSW), and anti-replay attacks.

Enterprise SSO Architecture & Zero Enterprise Tax
• Zero Enterprise Tax: Replaces WorkOS ($125/conn/mo) and Auth0 Enterprise ($800+/mo) with a completely self-hosted, MIT-licensed engine.
• Zero Native C++ Dependencies: 100% pure JavaScript XML canonicalization (C14N: http://www.w3.org/2001/10/xml-exc-c14n#) and cryptographic verification — runs seamlessly on Node.js, Express, and Cloudflare Workers (edge compute).
• Multi-Tenant SAML 2.0 Service Provider (SP): Dynamic SP Metadata XML generation at /auth/sso/saml/:id/metadata.xml with entity ID and ACS URL.
• Universal Domain Routing: Automatically resolves enterprise IdPs via resolveSso({ email }) with DNS TXT ownership verification (_devauth-verify.<domain>).
• Strict Cryptographic Security: XML Signature Wrapping (XSW) elimination, anti-replay assertion ID tracking, 5-minute clock skew tolerance, and dual rolling X.509 certificate rollover.
• JIT User & Org Provisioning: Automatic tenant account creation, organization binding, and tenant-scoped JWT generation upon SAML assertion.

3. Frontend Universal Domain Routing

client.js 
import { createDevAuthClient } from "devauthkit/client";

const devauth = createDevAuthClient({ baseUrl: "https://api.yourdomain.com" });

async function handleLogin(email) {
  // Automatically detects if email domain belongs to an enterprise SSO connection
  const sso = await devauth.resolveSso({ email });
  
  if (sso.isEnterprise) {
    // Redirects browser to Okta / Azure AD with signed Deflated SAML AuthnRequest
    devauth.loginWithSso(sso.connection.id, { redirectUrl: "/dashboard" });
  } else {
    // Fall back to Passwordless OTP, Magic Link, or Biometric Passkey
    await devauth.sendOtp({ email });
  }
}

SCIM 2.0 Directory Sync (RFC 7643 / RFC 7644)

Automated user and group lifecycle provisioning compliant with standard RFC 7643 and RFC 7644 protocols. Enables Okta, Microsoft Entra ID (Azure AD), and OneLogin to automatically provision accounts, update profile attributes, sync group memberships, and trigger instant deprovisioning cascades when employees leave the company.

Core SCIM 2.0 Architecture & Deprovisioning Defense
• Instant Deprovisioning Cascade: Setting active: false in Okta immediately removes workspace memberships and purges all active refresh tokens and sessions across all user devices.
• High-Entropy Bearer Tokens: SCIM directories authenticate via 256-bit cryptographically secure tokens (scim_...) stored securely as SHA-256 hashes.
• RFC 7643 / 7644 Compliance: Implements official schemas, ServiceProviderConfig, Users, and Groups endpoints conforming to enterprise IdP requirements.
• RFC 7644 PATCH Operations: Parses complex JSON-Patch replace operations (e.g., operations: [{ op: "replace", path: "active", value: false }]).
• Multi-Tenant Storage Adapters: Zero-latency in-memory and Cloudflare D1 SQL adapters support directory-to-organization tenancy binding.

Cryptographically Signed Webhooks (HMAC-SHA256)

Enterprise outbound event delivery engine conforming to the Svix / Stripe signature standard (DevAuth-Signature: t=${timestamp},v1=${signature}). Features anti-replay tolerance windows, constant-time verification, wildcard pattern subscriptions, non-blocking asynchronous dispatch, and delivery logging.

Core Webhook Security Architecture
• Svix / Stripe Standard: Headers format signature as DevAuth-Signature: t=...,v1=... over ${timestamp}.${rawBody}.
• Constant-Time Verification: Uses timing-safe equality to eliminate timing side-channel exploits.
• Anti-Replay Defense: Rejects requests with timestamps outside the tolerance window (default 300s) and future clock skew.
• Zero-Downtime Secret Rolling: Verifies against any valid v1 signature when rotating endpoint secrets.
• Non-Blocking Dispatch: Dispatches via microtasks without adding latency (< 1ms) to login or organization APIs.

Multi-Tenancy & Organizations (B2B Workspaces)

Turnkey B2B workspace isolation, member invitations with 256-bit cryptographic token hashing, tenant-scoped JWTs, dynamic workspace switching, and org-scoped RBAC/PBAC. Eliminates steep SaaS add-on fees ($$$/month).

Core Architecture & Security Highlights
• Tenant-Scoped JWTs: Switching workspaces issues a token scoped to org_id, org_role, and resolved permissions.
• Cryptographic Invitations: Secret 256-bit tokens are SHA-256 hashed before storage; raw tokens are never persisted in plaintext.
• Privilege Escalation Defense: Admins cannot grant the Owner role or demote owners; owners cannot abandon workspaces without transferring ownership.
• RFC 9449 DPoP Continuity: Preserves client hardware key thumbprints (cnf.jkt) across workspace context shifts.

RFC 9449 DPoP: Proof-of-Possession Token Binding

In standard OAuth 2.0 architectures, access tokens are Bearer tokens: anyone who extracts the token (via infostealer malware, malicious browser extensions, XSS, or proxy logs) can impersonate the user. DPoP eliminates token theft by binding credentials cryptographically to the client device.

Cryptographic Binding Mechanism
1. Client generates an ephemeral ECDSA P-256 keypair in device memory.
2. Server embeds the RFC 7638 SHA-256 thumbprint (cnf.jkt) into the JWT.
3. Client computes an ephemeral single-use signature containing the HTTP method, URI, timestamp, and token hash (ath).
4. If an attacker intercepts and replays the token, the server rejects it with 401 Unauthorized.

Implementation on Server and Client

server.js & client.js 
// Server configuration
devAuthKit(app, {
  dpop: true, // Activates RFC 9449 binding & replay protection store
  jwtSecret: process.env.JWT_SECRET
});

// Strict DPoP enforcement on sensitive routes
app.post("/api/transfer", devAuthKit.requireDPoP, (req, res) => {
  res.json({ success: true, dpopThumbprint: req.dpop.jkt });
});

// Client SDK initialization
const auth = new DevAuthClient({
  apiUrl: "http://localhost:3000",
  dpop: true // Transparent client-side P-256 signing
});
