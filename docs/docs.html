DevAuthKit Complete Documentation

DevAuthKit is a zero-config, plug-and-play self-hosted authentication toolkit for Node.js, Express, and Cloudflare Workers (Hono). It provides hardware-bound RFC 9449 DPoP token defense, WebAuthn passkeys, passwordless email OTP, rotating refresh tokens, and database adapters for Prisma, Drizzle, and Mongoose with zero monthly active user (MAU) billing limits.

npm install devauthkit

Quickstart Guide

Mount a production-ready authentication engine in less than 3 minutes.

const express = require("express");
const devAuthKit = require("devauthkit");

const app = express();

// Initialize DevAuthKit (Zero-config dev mode prints OTP to console)
devAuthKit(app, {
  jwtSecret: process.env.JWT_SECRET || "your-secret-key",
  sessionSecret: process.env.SESSION_SECRET || "your-session-key",
  corsOrigin: ["http://localhost:3000", "http://localhost:5173"],
  devMode: true
});

// Protect routes with triple-strategy requireAuth middleware
app.get("/api/dashboard", devAuthKit.requireAuth, (req, res) => {
  res.json({ message: "Authenticated", user: req.user });
});

app.listen(3000, () => console.log("DevAuthKit server ready on http://localhost:3000"));
import { Hono } from "hono";
import { createHonoAuth, CloudflareD1RefreshTokenStore } from "devauthkit/hono";

const app = new Hono();

export default {
  async fetch(request, env, ctx) {
    const auth = createHonoAuth({
      jwtSecret: env.JWT_SECRET,
      d1: env.DB,
      refreshTokenStore: new CloudflareD1RefreshTokenStore(env.DB)
    });

    app.route("/auth", auth.routes);

    app.get("/api/user", auth.requireAuth, (c) => {
      return c.json({ user: c.get("user") });
    });

    return app.fetch(request, env, ctx);
  }
};
import React from "react";
import { AuthProvider, useAuth } from "devauthkit/react";

function UserProfile() {
  const { user, isAuthenticated, sendOTP, verifyOTP, logout } = useAuth();

  if (!isAuthenticated) {
    return <button onClick={() => sendOTP("user@dev.io")}>Login with OTP</button>;
  }

  return (
    <div>
      <h2>Account: {user.email}</h2>
      <button onClick={logout}>Sign Out</button>
    </div>
  );
}

export default function App() {
  return (
    <AuthProvider>
      <UserProfile />
    </AuthProvider>
  );
}

RFC 9449 DPoP: Proof-of-Possession Token Binding

In standard OAuth 2.0 architectures, access tokens are Bearer tokens: anyone who extracts the token (via infostealer malware, malicious browser extensions, XSS, or proxy logs) can impersonate the user. DPoP eliminates token theft by binding credentials cryptographically to the client device.

Cryptographic Binding Mechanism
1. Client generates an ephemeral ECDSA P-256 keypair in device memory.
2. Server embeds the RFC 7638 SHA-256 thumbprint (cnf.jkt) into the JWT.
3. Client computes an ephemeral single-use signature containing the HTTP method, URI, timestamp, and token hash (ath).
4. If an attacker intercepts and replays the token, the server rejects it with 401 Unauthorized.

Implementation on Server and Client

server.js & client.js 
// Server configuration
devAuthKit(app, {
  dpop: true, // Activates RFC 9449 binding & replay protection store
  jwtSecret: process.env.JWT_SECRET
});

// Strict DPoP enforcement on sensitive routes
app.post("/api/transfer", devAuthKit.requireDPoP, (req, res) => {
  res.json({ success: true, dpopThumbprint: req.dpop.jkt });
});

// Client SDK initialization
const auth = new DevAuthClient({
  apiUrl: "http://localhost:3000",
  dpop: true // Transparent client-side P-256 signing
});

Rotating Refresh Tokens & Revocation

Short-lived access tokens paired with rotating httpOnly cookies and token family reuse detection.

Refresh Token Options 
devAuthKit(app, {
  refreshTokens: {
    accessTokenExpiresIn: "15m",
    refreshTokenExpiresInDays: 30
  },
  jwtSecret: process.env.JWT_SECRET,
  sessionSecret: process.env.SESSION_SECRET
});

// Endpoints automatically mounted:
// POST /auth/refresh            - Rotates cookie and issues new access token
// POST /auth/sessions/revoke    - Revokes current device token family
// POST /auth/sessions/revoke-all- Revokes all sessions across all devices

Rate Limiting & Brute-Force Shield

Fixed-window limits per IP and per email with automatic account lockout after 5 failed verification attempts.

Rate Limit Configuration 
devAuthKit(app, {
  rateLimit: {
    requestOtp: { perEmailMax: 5, perIpMax: 30 },
    verifyOtp: { perEmailMax: 10, perIpMax: 40 }
  }
});

Role-Based Access Control (RBAC)

Built-in middleware for granular route authorization based on verified user claims.

requireRole Middleware 
const { requireAuth, requireRole } = devAuthKit;

// Restrict endpoint to admin users only
app.get("/api/admin/metrics", requireAuth, requireRole(["admin", "superadmin"]), (req, res) => {
  res.json({ adminData: true, user: req.user });
});

Cloudflare Workers & Hono

Deploy auth directly to the edge using Hono, Cloudflare D1 serverless SQLite, and KV storage.

devauthkit/hono worker.js 
import { Hono } from "hono";
import { createHonoAuth, CloudflareD1RefreshTokenStore } from "devauthkit/hono";

const app = new Hono();

export default {
  async fetch(request, env, ctx) {
    const auth = createHonoAuth({
      jwtSecret: env.JWT_SECRET,
      d1: env.DB,
      refreshTokenStore: new CloudflareD1RefreshTokenStore(env.DB)
    });

    app.route("/auth", auth.routes);
    return app.fetch(request, env, ctx);
  }
};

React & Next.js Hooks (devauthkit/react)

Official React hooks and context provider for state synchronization across your UI.

useAuth Hook Example

function Dashboard() {
  const { user, isAuthenticated, isLoading, sendOTP, verifyOTP, logout } = useAuth();

Universal Client SDK (devauthkit/client)

Vanilla JavaScript SDK with automatic Bearer token injection, DPoP signing, and reactive storage listeners.

DevAuthClient Usage 
import { DevAuthClient } from "devauthkit/client";

const auth = new DevAuthClient({
  apiUrl: "http://localhost:3000",
  dpop: true // Enables hardware-bound token protection
});

// Send and verify OTP
await auth.sendOTP("alex@dev.io");
await auth.verifyOTP("alex@dev.io", "123456");

// Automatically attaches DPoP signature + Bearer header
const res = await auth.fetch("/api/dashboard");
const data = await res.json();

Full Configuration Reference

Every configuration option available when initializing DevAuthKit.

Option Type Default Description
jwtSecret string Required in prod Secret key for signing access JWT tokens.
sessionSecret string Required in prod Secret key for encrypting session cookies.
corsOrigin string | string[] [] Allowed frontend origins for CORS credentialed requests.
devMode boolean false Prints OTP codes and magic links to terminal if email is unconfigured.
dpop boolean false Enables RFC 9449 token binding & replay cache protection.
refreshTokens boolean | object false Enables rotating httpOnly refresh cookies (15m access, 30d refresh).
userAdapter UserAdapter In-memory Database adapter (Prisma, Drizzle, Mongoose, or custom).
magicLink boolean false Issues 1-click magic login links alongside OTP emails.
passkeys PasskeyOptions Disabled WebAuthn configuration with rpName, rpID, and origins.
rateLimit RateLimitConfig Enabled Fixed-window rate limits per IP and per email.
